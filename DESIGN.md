# Syllo interface system

The user selected VCI component patterns and rejected later inconsistent patches. The current UI uses one theme file, rebuilt as a coherent system rather than stacked overrides. Primary surfaces: white panels, neutral gray canvas and sidebar; Moodle orange #f98012 for actions/selection, accessible deep orange text, charcoal ink. No blue. Outfit for Latin and Source Han Sans SC for Chinese.

Homepage has no date/title introduction row. Every page shares the same top toolbar: semester selection, course adjustment, theme and refresh stay above the content beside search; non-home pages also expose the course selector there, and the assignment page keeps its status filters in the toolbar instead of repeating them inside the panel. The main column shows three compact current-course cards on desktop, with published-grade and course-announcement panels underneath, and a 340px assignment aside (330px on intermediate desktops). Homepage assignment-status filters sit beside the assignment heading; there is no redundant full-page link. DOM order matches visual reading order. Panels share iOS-inspired continuous corners, 1px gray borders and compact 12px padding. The navigation rail is inset with 30px corners; navigation and filters use pill selections, subtle elevation and directional arrows. These shapes come from the user's references; colors remain Moodle orange, white and neutral gray, never the reference's beige. Full lists scroll inside desktop panels; narrow and short viewports use page scrolling and never hide courses or grades.

Navigation changes use a 360ms Web Animations content slide with subtle blur and a 300ms selected-navigation press recovery; opacity stays constant to avoid flashes. Native View Transitions were rejected after the preview engine reported aborted prepaint transitions. Search, pinning and assignment filters do not trigger page entrances. Buttons have subtle hover lift and press feedback. Reduced-motion preferences disable transitions. Assignment filters remain on the current page. The timeline was removed at the user’s request. Courses and assignments are rounded tinted blocks. Course colors are assigned once and persisted per school, so same-course assignments share a background even after refresh or course-list reorder. Moodle orange remains the navigation/action color.

Course pages, resources and grades show full names, decoded from Moodle text. Actual course cover images replace fabricated code artwork; absent images leave a full-width text header without reserving an empty cover column. Opening a homepage course promotes that course to a full-row resource view while keeping the other courses available in the compact grid; this focus state never becomes a global course filter. Focused resources use two or three columns on desktop to avoid tall sparse pages. Homepage has a separate explicit current-semester grades section above course rows, including published component grades when the total is missing. No dead avatar. Footer has the official Moodle logo and Powered by credit.

The source data model supports immediate encrypted local cache, five-minute fresh-cache startup reuse, background refresh for older cache, six-hour reuse of course contents and bounded parallel requests. Full refresh bypasses response caches. Credentials never enter the renderer. Original school pages use Moodle mobile web autologin when the saved private token is available; legacy credentials need one fresh school login.
